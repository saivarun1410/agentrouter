## Agent roster

Generated by agentrouter from repository evidence. Specs live in `.agentrouter/roster.json`;
edit those rather than the rendered agent files.

### `ci-failure-analyst`

Pulls a failed CI run, reads the logs, and reports whether the failure is real or infrastructural. Use when a CI job has failed and the cause is not obvious from the job name — especially to distinguish a genuine regression from a flake, a cache miss, or a runner problem.

- **Justified by:** context-isolation, tool-scoping
- **Tools:** Bash, Read, Grep
- **Considered instead:** skill — rejected because a repo with one short CI job produces logs small enough to read inline, and the routine is better captured as a procedure

### `test-triage`

Runs the test suite, reads the full output, and reports only what failed and why. Use when tests need to be run and diagnosed — after a change, on a red suite, or to confirm a fix. Returns a minimal failure summary rather than raw log output.

- **Justified by:** context-isolation, tool-scoping
- **Tools:** Bash, Read, Grep, Glob
- **Considered instead:** skill — rejected because with a fast suite the output fits comfortably in the main thread, so a written procedure is enough and a separate agent only adds a round trip

## Considered and rejected

These were evaluated and did not qualify as agents here. They are listed so the
absence is a decision on the record rather than an oversight.

- **Convention reviewer** — This is a rule, not an agent. with no mechanised check to grade against, this is a set of constraints that should apply to every edit continuously — which is a rules file, not something invoked after the fact
- **Migration author** — This is a skill, not an agent. a repo that has written two migrations in its lifetime has no established convention to encode, and the naming rule is a one-paragraph procedure
- **Codebase explorer** — This is a skill, not an agent. in a small repository the main thread can read the relevant files directly, and delegating the search costs more than it saves
- **Dependency auditor** — This is a skill, not an agent. without recurring dependency work in the history there is no standing workload to isolate, and an occasional upgrade is better handled inline
- **Package fan-out worker** — This is a skill, not an agent. a single-package repository has nothing to fan out across, and the change is better made directly than delegated one target at a time
- **Docs contract keeper** — This is a rule, not an agent. without a stated documentation obligation there is nothing to check against, and "keep the docs current" is a standing constraint belonging in the rules file
- **API docs writer** — This is a skill, not an agent. with no machine-readable interface definition there is no rubric to check the prose against, and documentation written without the surrounding context of the main thread is usually worse, not better
